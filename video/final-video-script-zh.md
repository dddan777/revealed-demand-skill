# 真需求验证器最终合作视频逐字稿

建议成片时长：4 分 05 秒左右

视频形式：真人口播 + 小红书店铺订单证据 + Meoo 操作录屏 + Skill 输出卡片

核心记忆点：点赞是意见，付款是更贵的意见

## 发布物料

小红书封面主标题：我把 1000+ 次购买做成了一个 Skill

小红书笔记标题：卖出 1000+ 份后，我终于知道怎么判断“真需求”

## 0:00–0:20 Hook

画面：正面近景。前三秒直接切入，随后快速闪过已脱敏的订单或销量证据。

口播：

我卖得最好的一款 AI 产品，不是 SaaS，也不是 Agent，而是一份教人文社科学生怎么用大语言模型做文本分析的教案。它最后卖出了一千多份。

但这件事最重要的，不是“一份教案也能赚钱”，而是它让我真正理解了：什么叫真实需求。

屏幕大字：1000+ 次真实购买

## 0:20–0:50 反常识结论

画面：切到桌面，快速出现“功能更多”“先做平台”“先投流”三个词，再逐个划掉。

口播：

很多人做 AI 产品时，第一反应是继续加功能、做得更完整，或者先去投流。但市场不会因为你做得辛苦、功能很多，就自动付钱。

用户真正愿意买的，往往不是一个宏大的产品，而是一个他此刻就想解决、而且能马上看懂的具体问题。

所以，判断需求不能只问：“你想不想要？”真正要看的是：他愿意为这件事付出什么成本。

屏幕大字：别问想不想要，看他付出什么

## 0:50–1:25 真实案例拆解

画面：展示教案目录、使用步骤、交付样例。敏感信息全部打码。

口播：

当时，人文社科的学生和研究者已经开始接触大模型，但很多人不会写复杂代码，也不知道怎么把自己的文本材料，真正变成一个可以执行的分析流程。

我没有先做一个“大而全的 AI 科研学院”，也没有先开发一整套平台。我只切了一个最小结果：让一个不会复杂编程的人，拿着自己的文本材料，也能按步骤完成一次分析。

产品足够具体，理解成本低，使用路径短；价格也落在一个不需要反复开会、反复比较的决策区间。最后，一千多次真实购买，比一千个“想学”更有信息量。

屏幕大字：卖结果，不卖功能数量

## 1:25–1:55 经济学解释

画面：手写或动态图呈现“说想要 → 收藏 → 留资 → 付款 → 复购”。

口播：

经济学里有一个很重要的视角：不要只听人说自己偏好什么，要观察他在真实约束下怎么选择。

当然，付款也不是绝对真理。折扣、熟人关系、退款、渠道都可能影响结果。但它通常比点赞、收藏和问卷回答更接近真实承诺。

所以我把信号分成不同层级：看见，是注意力；收藏，是低成本兴趣；留资，是意向；付款，是交易证据；复购和转介绍，才更接近可重复需求。

屏幕大字：行为是证据，不是神谕

## 1:55–2:35 把经验做成 Skill

画面：进入 Meoo，创建 Skill，展示文件结构与 VOTE 四个字母。

口播：

这次和 Meoo 共创，我没有把这段经验写成一条很长的 Prompt，而是做成了一个可以重复执行的 Skill，叫“真需求验证器”，英文是 Revealed Demand。

它的核心是我设计的 VOTE 框架。

V，Value Moment，先找用户真正着急的价值时刻。

O，Observable Commitment，只看可观察、可分层的承诺行为。

T，Transaction Unit，把大产品切成最小可交易结果。

E，Experiment，用一个有明确阈值的实验，让市场决定下一步。

屏幕大字：VOTE = 价值时刻 × 行为承诺 × 交易单元 × 实验

## 2:35–3:20 Skill Demo

画面：录屏输入案例。左侧放输入，右侧逐步展开 Skill 输出。

演示输入：

我有一份教人文社科用户用大模型做文本分析的教案，历史累计卖出 1000+ 份。我想把它升级成更高价的课程或工具。请判断需求是否已经验证，并告诉我下一步。

口播：

如果我把这个案例丢进去，它不会直接告诉我：“已经验证成功，赶紧做高价课。”

它会先把事实、推断和缺失数据拆开。

事实是：我报告了超过一千次付费，这对历史教案构成很强的交易证据。

但缺失的是：当时的曝光分母、成交价格、退款率、用户来自哪里，以及有没有复购。

所以它给出的结论会非常克制：原来的教案有交易证据，但这不能自动证明更高价课程、订阅工具，或者一个新渠道也有需求。

然后，它只给我下一轮一个动作：不要同时换产品、换人群、换价格。先选择同一类用户，把“更高价但交付更完整”的版本做成一个小规模付费测试，提前写清通过、模糊和失败分别怎么办。

屏幕依次出现：

- 证据状态：历史交易证据
- 缺口：价格、分母、退款、渠道、复购
- 下一步：只验证一个扩展假设

## 3:20–3:45 固定输出与价值

画面：依次翻过《需求证据地图》《最小可卖单元卡》《价格实验表》《决策规则》四张卡。

口播：

最后，你拿到的不是二十条泛泛的增长建议，而是一张需求证据地图、一个最小可卖单元、一套价格实验，以及提前写好的决策规则。

数据通过，就做一次受控扩量；结果模糊，就先修复追踪；明确失败，就改包装、改假设，或者停止。每一轮只做一件能产生新证据的事。

屏幕大字：一次只做一个能改变决策的实验

## 3:45–4:05 结尾与 CTA

画面：回到正面口播，最后停在 Meoo 中的 Skill 名称与 GitHub 仓库页面。

口播：

以前我以为，做产品最难的是把功能做出来。后来我发现，更难的是让市场愿意投票。

如果你也做了一个 AI 产品，却还在纠结到底该加功能、投流还是降价，可以在 Meoo 里试试“真需求验证器”，也可以在 GitHub 查看完整公开结构。

记住一句话：点赞是意见，付款是更贵的意见；而复购，才是市场愿意再投一次票。

屏幕大字：Revealed Demand｜真需求验证器

## 拍摄与剪辑备注

- 订单与收入画面必须脱敏，只保留能证明“1000+ 次购买”的必要信息。
- “历史累计 1000+ 份”为创作者提供的事实；如发布前可导出平台截图，优先使用后台证据画面。
- Demo 中所有缺失字段要真实显示为“未提供”，不要补造数字。
- Meoo 录屏至少完整展示一次：输入 → 追问或边界判断 → VOTE 卡 → 下一轮实验。
- 口播中“更高价课程或工具”只是待验证扩展，不要呈现为已经发生的销售结果。
- 结尾 GitHub 画面使用公开仓库首页，停留 2–3 秒，确保仓库名和 README 标题清晰可读。
